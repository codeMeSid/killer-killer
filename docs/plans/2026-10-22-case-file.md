# Case-file co-op Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the round-based killer game with a co-op case file: open folders, live pins/markers, host accuses who+why+how with two guesses, reveal, leaderboards.

**Architecture:** Cases are repo folders written by the rewritten skill (`case.json` public, `solution.json` server-only). Route handlers judge guesses with a pure `src/lib/case/` module; Supabase tables hold rooms/members/pins/guesses/results; Realtime stays a payload-free doorbell plus presence (presence state carries which item each agent reads).

**Tech Stack:** Next.js 16 App Router, TS, Tailwind v4, Supabase (Postgres, anon auth, Realtime), node `--test`, Python 3 (skill scripts).

**Spec:** `docs/specs/2026-10-22-case-file-design.md`

## Global Constraints

- Palette, obsidian background, fonts, pixel frames, motion rules: CLAUDE.md §1, §10, §13 (type steps, disabled-button labels, counts in words) still bind.
- Every route returns `ok()/fail()` envelope (`src/lib/api.ts`).
- Game tables via `adminClient()` only; RLS on, no policies, no grants.
- Schema changes = new migration file; push only after user confirms `npx supabase db push`.
- Solution data never in any response while `status = 'playing'`.
- Scene SVGs render through `<img src="data:image/svg+xml,…">` (scripts can't run in `<img>`); validator still rejects `<script`, `on*=`, `foreignObject`, external `href`, non-palette hex.
- 375 / 768 / 1280 px, no horizontal scroll.
- Done = `npm test && npm run typecheck && npm run lint && npm run build` green.

## Review Focus

- Two host devices / double-click submit the same guess → exactly one guess row counted (Task 4 race check).
- Host accuses with zero suspects and without "No one" → 400 "Pick who did it", no guess burned (Task 2).
- Suicide case: correct answer = `who: []` ("No one") + motive + method; any suspect picked is wrong (Task 2).
- Non-host device POSTs a guess → 403, nothing consumed (Task 4).
- Ninth device joins → 409 lexicon `full` error, never a 500 (Task 4).

```ts
{ schema: "mm-case-file/1"; slug: string; title: string; difficulty: "easy"|"medium"|"hard";
  rating: "PG-13"|"mature"; setting: string; tone: string;
  victim: { name: string; summary: string }; brief: string;
  suspects: { name: string; role: string; relation: string; alibi: string; note: string }[]; // index = id
  folders: { id: string; kind: "suspects"|"statements"|"reports"|"evidence"|"documents"|"timeline"|"map"|"extras";
             title: string; items: Item[] }[];
  motives: { id: string; text: string }[];   // 4–6, shuffled, ids "m1".."m6"
  methods: { id: string; text: string }[] }  // 4–6, ids "h1".."h6"
Item = { id: string; title: string } & (
  | { kind: "note"; body: string }
  | { kind: "statement"; speaker: string; lines: { q: string; a: string }[] }
  | { kind: "report"; sections: { heading: string; body: string }[] }
  | { kind: "photo"; svg: string; caption: string }
  | { kind: "log"; rows: { at: string; text: string }[] }
  | { kind: "map"; svg: string; caption: string })
```
`solution.json`
```ts
{ schema: "mm-case-solution/1"; killers: number[]; // suspect indexes; [] = suicide/accident
  motive: string; method: string; story: string[];
  deductions: { claim: string; part: "who"|"why"|"how"; items: string[] }[];
  herrings: { suspect: number; ruled_out_by: string[] }[] }
```
Item ids unique across the case. Suspect cards come from `suspects`; the Suspects folder may add extra items.
